# Model connections design

Цель вкладки Mini App — правдиво показывать состояние аналитика Crisis Radar и назначения моделей для всех AI-задач. В self-hosted релизе выбор выполняется приватными переменными окружения backend: браузер не принимает и не хранит секреты.

## Реализовано: сменный read-only аналитик Crisis Radar

- Ollama на `http://127.0.0.1:11434` и модель `qwen3.5:9b`.
- Только localhost, без редиректов и без внешнего API-ключа.
- Ограниченный read-only контекст: рассчитанная стадия, группы, сценарии, индикаторы и пороги, официальный новостной контекст и календарь.
- JSON-ответ канонизируется на backend; одиночные строковые поля безопасно приводятся к массивам, лишние поля отбрасываются, ссылки на доказательства проходят серверный allowlist.
- Для каждого ответа сохраняются `grounded` и причины отклонения. Проверка охватывает основной текст, ограничения и подсказки: выдуманные числа, отсутствие доказательств, неверное число сценариев и смешение статуса сценария с уверенностью делают ответ непроверенным.
- Подозрительные команды внутри заголовков/описаний новостей удаляются до передачи модели. Оригинал остаётся в базе и обычной новостной ленте.
- Приватная история диалогов с проверкой владельца.
- Режимы `fast` и `deep` отличаются лимитом контекста и ответа, но не правами.
- API различает модель, установленную на диске, и модель, уже загруженную в память; холодный старт не блокирует кнопку запроса.
- После таймаута circuit breaker временно останавливает новые генерации, чтобы они не копились за продолжающим работать процессом Ollama. Успешный ответ удерживает модель в памяти ограниченное время.
- У модели нет инструментов записи: она не меняет сделки, сигналы, пороги или уведомления.
- Mini App показывает зелёную метку `проверено по данным / grounded in data` либо янтарную `требует ручной проверки / manual verification required`.
- Один и тот же строгий контракт доступен для `ollama`, официального `openai`, официального `anthropic` и `openai-compatible` endpoint.
- Провайдер выбирается приватно на backend через `CRISIS_AGENT_PROVIDER`; ключ не сохраняется в браузере и никогда не возвращается в Mini App.
- Remote endpoint проходит URL-policy, redirects отключены, context ограничен, а ошибки не содержат API key.

Живой RU/EN regression-набор запускается отдельно, поскольку обращается к локальной Ollama и измеряет реальное время ответа:

```bash
python -m scripts.evaluate_crisis_agent --mode fast --timeout 120 --runs 2 --pause 2
python -m scripts.evaluate_crisis_agent --case en_news_prompt_injection --mode fast --timeout 120
```

По умолчанию live-eval прекращает серию после первого таймаута, чтобы не создавать очередь на машине с ограниченной памятью. В итоговой строке он показывает число попыток, таймауты и задержки p50/p95.

На Mac с 16 ГБ `qwen3.5:0.8b` была отдельно проверена 2026-07-21 как кандидат для быстрого режима. Контрольный RU-кейс занял 30,251 мс и не прошёл grounding/evidence-проверку: модель не вернула допустимое доказательство и исказила смысл группы риска. Поэтому она установлена только для экспериментов и не назначена рабочим аналитиком. Безопасный детерминированный fallback остаётся активным; `qwen3.5:9b` или настроенный облачный провайдер подходят для глубокого режима после успешного live-eval на целевом сервере.

Переменные окружения:

```env
CRISIS_AGENT_ENABLED=true
CRISIS_AGENT_PROVIDER=ollama
OLLAMA_BASE_URL=http://127.0.0.1:11434
CRISIS_AGENT_MODEL=qwen3.5:9b
CRISIS_AGENT_API_KEY=
CRISIS_AGENT_BASE_URL=
ANTHROPIC_API_KEY=
CRISIS_AGENT_TIMEOUT_SECONDS=90
CRISIS_AGENT_RATE_LIMIT=6
CRISIS_AGENT_KEEP_ALIVE_MINUTES=10
CRISIS_AGENT_COOLDOWN_SECONDS=120
```

## Пользовательский сценарий

1. Пользователь открывает вкладку `Модели`.
2. Видит карточки:
   - `OpenAI API` — облачная модель по ключу.
   - `Local OpenAI-compatible` — локальный сервер с endpoint вида `/v1/models` и `/v1/responses` или `/v1/chat/completions`.
   - `Manual/offline` — без модели, бот использует ручные шаблоны.
3. В каждой карточке есть свернутая инструкция:
   - что установить/где взять ключ;
   - какие поля заполнить;
   - как проверить соединение;
   - что будет отправляться в модель.
4. В текущем self-hosted релизе владелец сохраняет подключение только в приватном `.env` на backend. UI-сохранение ключа намеренно не имитируется.
5. Backend проверяет соединение и доступность выбранной модели через status endpoint провайдера.
6. Mini App читает и показывает фактические backend-привязки задач:
   - `vision_trade_extraction` — распознавание сделки по скрину;
   - `journal_summary` — разбор дневника;
   - `obsidian_report` — генерация расширенных отчетов;
   - `trade_review` — LLM-комментарий к сетапу.
7. Изменение провайдера выполняется в приватном `.env` с перезапуском backend. Интерфейс не имитирует несуществующее сохранение и не показывает секрет даже маской.

## Безопасность

- API keys нельзя отдавать обратно в Mini App.
- Текущий UI вообще не принимает ключи и не показывает даже их маску.
- Ключи текущего релиза хранятся только в приватном окружении backend.
- Если UI-менеджер будет реализован позже, секреты должны храниться зашифрованными или через системное secret-хранилище и возвращаться только маской.
- Все операции требуют Telegram auth текущего пользователя.
- Проверка `/v1/models` не должна логировать ключ, полный base URL с секретами или prompt.
- Для локальных моделей base URL разрешается только из allowlist-схем: `http://127.0.0.1`, `http://localhost`, private LAN или явно настроенный HTTPS.

## Опциональное расширение после self-hosted релиза

- Зашифрованное или OS-keychain хранилище ключей для редактирования через Mini App.
- CRUD подключений и маскированное отображение секрета.
- Получение каталога моделей для выбора в интерфейсе.
- Переключение task bindings без ручного изменения `.env`.

Это удобство администрирования, а не незавершённая функция аналитического ядра: текущие Ollama/OpenAI/Anthropic/OpenAI-compatible подключения и ручные fallback уже выбираются backend-конфигурацией.

## Возможные дальнейшие улучшения

- Кнопка “проверить скрин на тестовом изображении”.
- Расширенные инструкции для локальных runtimes.
